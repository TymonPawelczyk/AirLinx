# AirLinx 0.1.1

A maintenance release with H.265 mirroring as an opt-in, and robustness fixes across discovery, Cast, DLNA, the media server and settings. Nothing is installed on the TV, and the app's interface is still in Polish.

Project page (Polish): https://tymonpawelczyk.github.io/AirLinx/

## Highlights

- **H.265 (HEVC) for Cast mirroring**, opt-in in Settings > Obraz > Kodek. AirLinx offers it only when the TV lists it and falls back to H.264 in the same session if the TV rejects it or the encoder fails. The default stays H.264.
- **File playback over the verified Cast channel.** Cast media playback now uses AirLinx's own CASTv2 connection, so the TV identity check covers it too. `pychromecast` and `protobuf` are no longer dependencies.
- **Tighter media server.** File and stream URLs are bound to the TV's address and expire after a sliding idle period. Malformed `Range` and `?t=` requests get 416/400 instead of a server error.
- **More reliable discovery** after network changes, with bounded scans and no false "offline" for a slow TV.
- **Safer state files and settings.** A corrupt `known_tvs.json` keeps its pins until "trust again", settings values are validated, and a damaged audio-routing state file no longer blocks cleanup.
- **DLNA consent per session.** Consent to DLNA without Cast verification is remembered for the playback session and tied to the TV endpoint and player.
- **Virtual TV** for developers: a local Cast and DLNA receiver for end-to-end tests without a TV.

The full list is in [CHANGELOG.md](https://github.com/TymonPawelczyk/AirLinx/blob/v0.1.1/CHANGELOG.md).

## Install or upgrade

Requirements: GNOME in an Xorg session (tested on Zorin OS 17.3 / Ubuntu 22.04), a TV with Google Cast or DLNA on the same network.

```bash
git clone --branch v0.1.1 https://github.com/TymonPawelczyk/AirLinx
cd AirLinx
./install.sh               # add --autostart to start hidden in the tray after login
```

To upgrade an existing install, check out `v0.1.1` in your clone and run `./install.sh` again. The system packages are the same as in [0.1.0](https://github.com/TymonPawelczyk/AirLinx/blob/v0.1.1/README.md).

## Known issues

- X11 only. In a Wayland session AirLinx shows a warning, and screen capture does not work.
- The "Balans" and "Kino" quality profiles are experimental.
- H.265 mirroring has not yet been confirmed on a real TV; keep H.264 if the picture misbehaves.
- Tested on one TV only (Samsung S85F). Other Cast devices and DLNA renderers may behave differently.
- File playback and DLNA mirroring use unencrypted HTTP in the LAN, protected by a random token in the URL. Only Cast mirroring is encrypted. Use AirLinx on a network you trust.

Report bugs in [Issues](https://github.com/TymonPawelczyk/AirLinx/issues) and vulnerabilities privately as described in [SECURITY.md](https://github.com/TymonPawelczyk/AirLinx/blob/v0.1.1/SECURITY.md).
