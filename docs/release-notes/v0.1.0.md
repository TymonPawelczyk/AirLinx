# AirLinx 0.1.0

First public release. AirLinx sends a Linux desktop (GNOME on Xorg) to a TV on the home network: it mirrors a monitor or a window with sound over Google Cast, and plays video, music and photos from disk through the TV's Cast or DLNA receiver. Nothing is installed on the TV. The app's interface is in Polish.

Project page (Polish): https://tymonpawelczyk.github.io/AirLinx/

## Highlights

- **Cast screen mirroring** of a whole monitor or a single window, with cursor and sound. Measured on a Samsung S85F with the "Gra / praca" profile: 1080p at 60 fps, 12 Mb/s, about 111 ms from screen to TV.
- **TV identity check.** The TV must pass Cast device authentication, and its identity is pinned on first use. AirLinx never silently drops from authenticated Cast to unencrypted DLNA; it asks first.
- **DLNA fallback** for mirroring and media when Cast is not available.
- **Media playback** with direct play, on-the-fly remux (MKV to fragmented MP4 for Cast) or transcode, a queue, and text subtitles (SRT, ASS, WebVTT).
- **Audio source**: system output, microphone, both, or a single application.
- **NVENC or libx264**: NVIDIA GPUs encode with NVENC, everything else falls back to libx264, for Cast and DLNA mirroring alike.
- **Tray icon and autostart**, close-to-tray, and a clean STOP on the TV when quitting.

The full list is in [CHANGELOG.md](https://github.com/TymonPawelczyk/AirLinx/blob/v0.1.0/CHANGELOG.md).

## Install

Requirements: GNOME in an Xorg session (tested on Zorin OS 17.3 / Ubuntu 22.04), a TV with Google Cast or DLNA on the same network.

```bash
sudo apt install git ffmpeg python3-gi python3-venv gir1.2-gtk-3.0 gir1.2-webkit2-4.1 \
  x11-xserver-utils x11-utils pulseaudio-utils
git clone --branch v0.1.0 https://github.com/TymonPawelczyk/AirLinx
cd AirLinx
./install.sh               # add --autostart to start hidden in the tray after login
```

The installer needs no sudo and installs into `~/.local`. Remove it with `./install.sh --uninstall` (settings in `~/.config/airlinx` are kept). See the [README](https://github.com/TymonPawelczyk/AirLinx/blob/v0.1.0/README.md) for details.

## Known issues

- X11 only. In a Wayland session AirLinx shows a warning, and screen capture does not work.
- The "Balans" and "Kino" quality profiles are experimental; their latency has not been measured.
- Tested on one TV only (Samsung S85F). Other Cast devices and DLNA renderers may behave differently.
- File playback and DLNA mirroring use unencrypted HTTP in the LAN, protected by a random token in the URL. Only Cast mirroring is encrypted. Use AirLinx on a network you trust.
- Latency of DLNA mirroring and of libx264 encoding has not been measured. AMD and Intel GPUs use libx264 (no VAAPI).

Report bugs in [Issues](https://github.com/TymonPawelczyk/AirLinx/issues) and vulnerabilities privately as described in [SECURITY.md](https://github.com/TymonPawelczyk/AirLinx/blob/v0.1.0/SECURITY.md).
